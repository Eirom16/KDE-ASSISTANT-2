## Modelos y capacidades

La UI ya no propone `llama-3.3-70b-versatile` para una nueva selección de Groq. Sugiere `openai/gpt-oss-120b`; no cambia un modelo guardado ni garantiza acceso a la sugerencia. Consultar modelos usa `GET /models` con la URL y credencial del borrador seleccionado, sin guardar y sin consultas automáticas. Se exige `data[]`, se deduplican IDs, se omiten entradas `active:false` y se filtran nombres claramente no destinados a chat. Es una heurística, no descubrimiento completo de capacidades multimodales. Un catálogo vacío/ausencia del modelo se comunica explícitamente.

La documentación de [retiros de Groq](https://console.groq.com/docs/deprecations) anuncia la retirada de Llama 3.1 8B Instant/Llama 3.3 70B Versatile el 16/08/2026 y recomienda GPT OSS. El [catálogo](https://console.groq.com/docs/models) aún los lista como Enterprise: la cuenta y `/models` prevalecen sobre asumir que todo usuario obtiene 404. El helper histórico de recomendaciones no se aplica automáticamente.

La [compatibilidad OpenAI de Groq](https://console.groq.com/docs/openai) admite este endpoint y rechaza campos como logprobs/logit_bias/messages.name. No se envían. Se valida temperatura 0–2; Groq transforma cero a un valor positivo mínimo. La [referencia Chat Completions](https://console.groq.com/docs/api-reference) depreca `max_tokens` en favor de `max_completion_tokens`; límites de contexto/salida y opciones de razonamiento dependen del modelo. No se inventan parámetros de razonamiento específicos ni se reintenta con otros parámetros a escondidas.

[Tool use](https://console.groq.com/docs/tool-use/overview) documenta herramientas locales para GPT OSS 20B/120B y falta de llamadas paralelas en esas familias. La solicitud del chat desactiva paralelismo en Groq; la ejecución y consentimiento siguen siendo F2. La prueba de conexión no ofrece ni ejecuta herramientas. Ningún mock certifica tool calling real de una cuenta/modelo de Groq.

## Destino y credenciales

Los proveedores conocidos advierten y bloquean el envío cuando el origen efectivo difiere de su preset. La confirmación explícita se vincula a proveedor y URL alternativa exacta; cambiarla exige nueva confirmación. Se aplica a catálogo, chat, diagnóstico y STT API antes de usar credenciales guardadas o de entorno. Personalizado mantiene URLs explícitas; loopback sigue disponible mediante aprobación. La captura Groq/fixture-chat/127.0.0.1 es una prueba simulada, con aprobación visible; no demuestra un defecto productivo de Groq.

La auditoría añade pruebas de redirección entre dos servidores (el segundo no recibe nada), respuestas superiores a 2 MiB, destinos no aprobados y STT sin reintentos. No se realizaron pruebas DNS/TLS con servicios reales: errores de transporte se agrupan en `network`; timeout se distingue.

## Probar conexión

`POST /api/ai-test` utiliza el borrador: catálogo autenticado, verificación del ID seleccionado y una petición Chat Completions `stream:true` de hasta 64 tokens con texto fijo. No manda el historial ni guarda cambios. Puede generar consumo real: la UI lo indica antes de pulsar el botón. En esta fase sólo se ejecutó contra loopback.

Se exige framing SSE válido, choices/delta y `[DONE]`. Un corte de transporte no es éxito. Para un modelo de razonamiento, `finish_reason:length` devuelve `limited:true` y comunica streaming limitado, sin afirmar respuesta completa. Esta excepción pertenece sólo al diagnóstico: no relaja el parser de conversaciones F1B. Timeout total de prueba 25 s, peticiones de 12 s; catálogo independiente 20 s; conexión TCP hasta 8 s; sin redirecciones de credenciales ni retries de aplicación o de protocolo.

| Resultado | Categoría / acción |
| --- | --- |
| 401 remoto | `invalid_key`: reemplazar clave |
| 403 | `forbidden`: revisar permisos de cuenta/modelo |
| Modelo ausente o code model_not_found/decommissioned | `model_not_found`: consultar catálogo |
| 404 sin código de modelo | `not_found`: revisar URL y recurso; no afirmar que sea una clave inválida |
| 402 / códigos de cuota conocidos | `quota`: revisar saldo/cuota |
| 429 genérico | `rate_limit`: esperar/revisar límites; no inventar falta de saldo |
| 5xx remoto | `provider_unavailable`: proveedor temporalmente fallido |
| DNS/TCP/TLS o timeout | `network` / `timeout` |
| JSON/SSE inválido o interrumpido | `protocol` / `provider_stream` |
| 400 / parámetros incompatibles | `parameters`: revisar modelo/opciones |
| 3xx | `redirect`: usar una URL final de confianza |
| 401 del backend local | Mensaje de autenticación local; no se atribuye al proveedor |

Los fallos remotos se devuelven como HTTP local 502 con categoría y `provider_status` cuando existe. Un fallo de escritura local es 500. No se devuelven cuerpos remotos, claves, URLs de petición o errores reqwest sin filtrar. Las categorías siguen los [errores oficiales de Groq](https://console.groq.com/docs/errors); no se garantiza que todo proveedor use los mismos códigos de cuota.

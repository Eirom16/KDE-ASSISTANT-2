# F3.5 — Reparación y rediseño de Configuración

Fecha: 2026-10-17. Baseline verificado: rama `recovery/f3-kde-wayland-integration`, HEAD `1d2186e5dae78ae9ddc1dbed01c44c9b7d67f920`. Trabajo en `recovery/f3.5-settings-providers`.

## Diagnóstico con límites explícitos

Se leyeron AGENTS, PLAN/PROMPT v2, apple-DESIGN y contratos F1B1, F1B2, F1B3A, F1B3B, F2 y F3. El índice estaba vacío. Había documentación histórica sin seguimiento; se conservó y no se utilizó reset/clean. No se inspeccionaron ni utilizaron credenciales personales.

1. **Campos vacíos no demostraban pérdida del archivo.** El GET de configuración del baseline ya redactaba las claves y el POST conservaba campos vacíos. SettingsDialog trataba el mapa redactado como si contuviera las claves y sólo mostraba un aviso general referido al proveedor activo. Faltaba estado de credencial por proveedor y una operación explícita de eliminación. El flujo sintético demuestra conservación tras reiniciar procesos completos; no atribuye retrospectivamente el incidente personal a una escritura perdida.
2. **Guardado incompleto como interacción.** El baseline ya comprobaba HTTP 200 antes de emitir `saved`; no se afirma que todo error HTTP produjera «Guardado». Sin embargo, no comprobaba el acknowledgement del body, no mostraba errores de carga, permitía editar antes de una carga válida y carecía de exclusión de peticiones/timeout del formulario. F3.5 exige 200 + `status:ok`, conserva el panel ante errores y vuelve a leer después de éxito. El mock cubre tanto 500 como 200 sin confirmación.
3. **Groq ofrecía un modelo obsoleto como preset.** SettingsDialog proponía `llama-3.3-70b-versatile`. La documentación oficial anuncia retirada estándar y excepciones Enterprise; el catálogo accesible a la cuenta decide. El helper histórico de recomendaciones no tenía callers: no había migración automática efectiva. Se actualizó la sugerencia de nuevas selecciones y se mantuvo intacta la elección guardada. No se declara ésta como causa definitiva del fallo de una cuenta no probada.
4. **Diagnósticos insuficientes.** El catálogo devolvía errores remotos como texto/snippets y HTTP 200, sin distinguir consulta de modelos y prueba de inferencia. F3.5 comparte transporte, selección de credenciales y clasificación segura entre diagnóstico y chat, añade prueba independiente y evita imprimir cuerpos remotos/errores reqwest con URLs.
5. **Jerarquía visual.** General concentraba proveedor, buscador, rejilla de presets, credenciales y tema; otras pestañas mezclaban controles pequeños de varios tamaños. Se sustituyó por navegación y formulario consistentes, sin WebEngine.

## IMPLEMENTED

- Estado `stored/environment/none`; conservar/reemplazar/eliminar claves con tombstone por proveedor, sin contaminación de fallback OpenRouter en custom/local. Migración conservadora sin reactivar eliminaciones; valores ambiguos preservados privadamente e inactivos, sin reescribir el archivo al iniciar. Debug de AiConfig redactado.
- Persistencia mediante el escritor privado atómico F1/F3 existente, copia anterior y publicación de memoria sólo tras éxito. Validación adicional y errores estáticos de escritura. No se inventó un segundo formato de almacenamiento.
- `/api/ai-models` y `/api/ai-test` autenticados. Probe independiente con catálogo, modelo y SSE; límite explícito de 64 tokens y estado limitado para razonamiento. Errores 401/403/404/429/cuota/5xx/red/timeout/protocolo diferenciados; bodies remotos excluidos. No hay retry automático de aplicación/protocolo ni redirecciones de credenciales. Destinos alternativos conocidos exigen aprobación explícita.
- Groq usa `max_completion_tokens`; herramientas siguen siendo opcionales y solicitan ejecución no paralela. OpenRouter es el único que lleva Referer/X-Title. F2 conserva toda su autoridad.
- Siete secciones, botones/campos de altura uniforme, navegación adaptable, foco y ciclo Tab/Shift+Tab, Escape, desplazamiento al foco, estados persistentes de lectura/guardado/prueba. Se conservan controles heredados de memoria, voz, personaje y atajos; no se implementan motores F4/F5.
- Harness reproducible de proveedores loopback, Quick Test y ejecutable real con copias de recursos/perfil XDG privados. Las modificaciones temporales de Main para conducir el test no se incluyen en producción.

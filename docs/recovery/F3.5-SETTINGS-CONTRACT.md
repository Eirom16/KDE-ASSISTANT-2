# F3.5 — Contrato de Configuración

Fecha: 2026-10-17. Baseline: `1d2186e5dae78ae9ddc1dbed01c44c9b7d67f920`.
Rama de trabajo: `recovery/f3.5-settings-providers`. Consolidación local condicional documentada en los artefactos de cierre; sin push, merge ni release.

## Autoridad y compatibilidad

Se conservan F1B, el journal, F2 y F3. Configuración es una acción de la UI local autenticada, no una herramienta del LLM. No se modifica `dispatch_permission`, el catálogo restringido, los consentimientos, GlobalShortcuts, SQLite ni el pipeline de audio. El consumidor STT API comparte ahora las protecciones de transporte y destino. Habilitar tool calling no autoriza una operación sensible.

El formato persistido sigue siendo `config.json` con campos snake_case. Una configuración antigua que sólo tiene `ai.api_key`, `base_url` y `model` se normaliza en memoria al perfil activo; el arranque no reescribe el archivo. Si ya hay claves por proveedor, una clave antigua idéntica se deduplica sin reemplazar entradas vacías. Una clave antigua distinta se conserva en `api_key`, inactiva y redactada, sin adivinar a qué proveedor pertenece. GET sólo indica `has_unassigned_legacy_key`; Privacidad permite eliminarla explícitamente mediante `delete_legacy_key`. El POST conserva esta clave si no se autoriza eliminarla. Ninguna migración reactiva tombstones ni usa esa clave ambigua como fallback.

Los campos planos de URL y modelo son espejos del perfil activo. Tras existir mapas, cambiar de proveedor no toma prestados los valores planos de otro: la URL usa su preset y el modelo requiere selección explícita si no hay perfil. La UI conserva borradores por proveedor. Los campos ajenos siguen viajando en el documento completo.
Cada proveedor tiene su clave, URL y modelo en mapas separados. Groq y xAI/Grok tienen IDs distintos. IDs inválidos se rechazan; no se convierten silenciosamente en OpenRouter. Sin clave, el chat y diagnóstico no contactan proveedores remotos/personalizados; LM Studio y Ollama admiten su servicio local sin clave. No hay fallback de `custom`, LM Studio u Ollama a `OPENROUTER_API_KEY`.

## Lectura y credenciales

`GET /api/config` conserva bearer, Host y Origin F3. Devuelve `api_key: ""`, `provider_keys: {}`, `has_api_key`, `configured_provider_keys` y `credential_states` por proveedor: `stored`, `environment`, `none`. Ninguna clave guardada o de entorno vuelve al formulario.

La UI muestra «Clave configurada» y la fuente. El input de contraseña contiene únicamente reemplazos escritos en esa visita. Vacío conserva la clave; **no** significa eliminación. Cambiar de proveedor conserva cada borrador por separado. Cerrar descarta borradores de credenciales.

`POST /api/config` exige el `config_revision` recibido en GET y admite el documento Config existente y el campo adicional `delete_provider_keys: [id, ...]`. Una clave no vacía reemplaza sólo la entrada de su proveedor. Las entradas vacías recibidas conservan las previas. La eliminación explícita tiene precedencia y persiste una entrada vacía que desactiva también el fallback de entorno. Es posible reemplazarla posteriormente con una nueva clave. El formulario retira una eliminación pendiente cuando se escribe un reemplazo.

Eliminar la credencial activa **no** ofrece borrado forense: la copia privada `config.json.bak`, snapshots o bloques del dispositivo pueden conservar datos anteriores. Se explica en Privacidad.

## Publicación, errores y recuperación

Se usa el escritor privado existente: directorios 0700, archivos regulares del UID, nlink=1, rechazo de symlinks, temporal exclusivo 0600, escritura y fsync, rename y fsync del directorio. Antes de publicar se actualiza atómicamente la copia privada de la configuración previa. I/O de archivos corre en `spawn_blocking`, fuera de Qt. El lock de configuración serializa las actualizaciones; la copia en memoria sólo cambia tras `save()` exitoso.

Se valida proveedor, URL HTTP(S) sin userinfo/query/fragmento, modelo no vacío, temperatura 0–2, tokens 1–131072 y forma de credenciales. Un error antes de publicación conserva el archivo y el estado anterior; el harness comprueba bytes y estado en memoria ante un backup symlink. No se certifica recuperación de averías físicas: un error de fsync posterior a rename puede dejar una publicación de durabilidad incierta. Nunca se devuelve éxito en ese caso; se debe volver a leer/reiniciar para comprobar el estado.

Éxito HTTP exige `200 {"status":"ok"}` tras publicar. La UI no emite `saved`, no muestra Guardado y no cierra ante HTTP fallido, respuesta inválida, 200 sin ese acknowledgement, autenticación local fallida, desconexión o timeout. La UI queda abierta también en éxito y vuelve a leer la vista redactada. No se puede guardar antes de una lectura válida ni mientras otra petición de Configuración esté pendiente. Timeout UI: 30 s; se invalidan callbacks obsoletos antes de abortar.

Sólo archivo inexistente permite bootstrap restrictivo. Corrupción/acceso inválido bloquean el arranque y conservan el archivo, como F1/F3. No se carga automáticamente una copia que pudiera reactivar capacidades. Recuperación manual: detener el proceso del perfil, conservar el corrupto con nombre privado distinto, revisar una copia válida y restaurarla como `config.json` privado, luego relanzar. El harness realiza esta secuencia con el backup generado por la aplicación, conserva el corrupto y relanza backend y QML.

El guardado completo usa revisión optimista opaca, calculada sobre la configuración completa con nonce privado por proceso. Bajo el lock de escritura se exige la revisión vigente: sin revisión devuelve 428 y con revisión obsoleta 409, sin escritura ni mezcla parcial. Incluye cambios de credenciales redactadas y otras acciones internas; un reinicio invalida revisiones anteriores. No ofrece concurrencia multi-proceso sobre un mismo perfil fuera del ciclo de vida F3 ni detecta edición manual externa del archivo.

Los destinos conocidos cuyo origen difiere del preset requieren aprobación explícita vinculada al proveedor y a la URL alternativa exacta (`provider_endpoint_approvals`). Cambiarla revoca su validez. El backend aplica esta condición antes de enviar chat, catálogo, diagnóstico o audio API; la UI advierte el destino oficial y el destino efectivo. Personalizado conserva su intención explícita; los fixtures de loopback deben aprobar sus endpoints. El cliente prohíbe redirecciones y retries automáticos, incluidos los retries de protocolo de reqwest.

## Interfaz

Siete secciones: General, IA y proveedores, Apariencia, Voz, Herramientas y permisos, Privacidad y datos, Avanzado. Navegación lateral en ancho amplio y selector en compacto. Los ajustes heredados de personaje se despliegan bajo Apariencia; transcripción API y atajos quedan en Avanzado. La memoria conserva sus acciones inmediatas y las identifica por separado de Guardar cambios.

SettingsButton, SettingsChoice, SettingsField y SettingsToggle reutilizan Theme; controles de acción/campos de 44 px, navegación de 52 px con etiquetas multilínea, foco visible y Switch accesible. Pie fijo, formulario con scroll vertical, scroll al foco y al cambiar de sección. Tab y Shift+Tab cierran el ciclo dentro del panel; Escape cierra cuando no existe petición pendiente. No se añade WebEngine.
